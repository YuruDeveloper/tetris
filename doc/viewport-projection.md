# Viewport 투영: 픽셀 좌표계로의 전환

## 1. 현재 문제 분석

### 증상
정가각형을 그렸는데 화면에서 길죽하게 렌더링됨

### 원인
현재 vertex shader는 NDC(Normalized Device Coordinates)를 직접 사용하는데, viewport의 aspect ratio를 고려하지 않음.

**현재 코드** (`public/vertexShader.vs`):
```glsl
vec2 finalLocation = vertex * size + location;
gl_Position = vec4(finalLocation, 0, 1);
```

**문제 상황**:
- 윈도우 크기: 480x720 (aspect ratio 2:3)
- NDC 공간: x축과 y축 모두 -1~1 범위
- NDC에서 0.2x0.2 정사각형 입력
  - 화면에서는 (480 * 0.2) x (720 * 0.2) = **96px x 144px 직사각형**으로 렌더링됨

NDC는 정규화된 좌표계이므로, 동일한 크기 값이 실제 픽셀로 변환될 때 viewport 비율만큼 왜곡됨.

---

## 2. 해결 방법 비교

### 2.1 Aspect Ratio 보정

**개념**: NDC 좌표계를 유지하면서, x 또는 y축에 aspect ratio를 곱해서 찌그러짐 제거

**방식**:
```glsl
float aspectRatio = 480.0 / 720.0;  // 0.666...
vec2 finalLocation = vertex * size + location;
finalLocation.x *= aspectRatio;  // x축만 보정
gl_Position = vec4(finalLocation, 0, 1);
```

**특징**:
- ✅ 구현 간단
- ✅ 기존 NDC 좌표계 유지
- ❌ 여전히 추상적인 좌표계 (-1~1 범위)
- ❌ 다른 게임 엔진과 좌표계가 다름

**사용 예시**:
- `size = (0.2, 0.2)` → 화면에서 정사각형으로 보임

---

### 2.2 Viewport 투영 (픽셀 좌표계) ← **선택**

**개념**: 픽셀 단위 좌표를 입력받아 shader에서 NDC로 변환

**방식**:
```glsl
vec2 pixelPos = vertex * size + location;
vec2 ndc = (pixelPos / viewportSize) * 2.0 - 1.0;
ndc.y = -ndc.y;  // y축 반전
gl_Position = vec4(ndc, 0, 1);
```

**특징**:
- ✅ 직관적인 픽셀 좌표계
- ✅ Unity, Godot 등 다른 엔진과 유사
- ✅ Aspect ratio 자동 해결
- ✅ 화면 크기 변경 시 대응 용이

**사용 예시**:
- `size = (100, 100)` → 100x100 픽셀 정사각형

---

### 비교 표

| 항목 | Aspect Ratio 보정 | Viewport 투영 |
|------|-------------------|---------------|
| **좌표계** | NDC (-1~1) | 픽셀 (0~width, 0~height) |
| **입력 예시** | (0.2, 0.2) | (100, 100) |
| **직관성** | 낮음 (추상적) | 높음 (픽셀 단위) |
| **다른 엔진 유사성** | 낮음 | **높음** |
| **Aspect ratio** | 수동 보정 필요 | 자동 해결 |
| **좌표 의미** | 화면 비율 | 실제 픽셀 크기 |

---

## 3. Viewport 투영 원리

Viewport 투영은 **픽셀 좌표(screen space) → NDC(Normalized Device Coordinates)** 변환 과정입니다.

### 3.1 전체 수식

```glsl
vec2 ndc = (pixelPos / viewportSize) * 2.0 - 1.0;
ndc.y = -ndc.y;
```

### 3.2 단계별 변환 과정

**예시 조건**:
- 윈도우 크기: 480x720
- `size = (100, 100)` (100x100 픽셀 정사각형)
- `location = (240, 360)` (화면 중앙)
- `vertex = (0.5, 0.5)` (사각형의 우상단 꼭지점)

#### Step 1: 픽셀 좌표 계산

```glsl
vec2 pixelPos = vertex * size + location;
```

**계산**:
```
pixelPos = (0.5, 0.5) * (100, 100) + (240, 360)
         = (50, 50) + (240, 360)
         = (290, 410)
```

**의미**: 화면에서 실제 픽셀 위치 (x=290px, y=410px)

---

#### Step 2: 정규화 (0~1 범위)

```glsl
vec2 normalized = pixelPos / viewportSize;
```

**계산**:
```
normalized = (290, 410) / (480, 720)
           = (0.604, 0.569)
```

**의미**:
- x축: 화면 왼쪽 끝(0) ~ 오른쪽 끝(1)
- y축: 화면 위 끝(0) ~ 아래 끝(1)
- **범위: [0, 1]**

**변환 대응표** (x축 예시):

| 픽셀 좌표 | 정규화 |
|-----------|--------|
| 0 (왼쪽 끝) | 0.0 |
| 240 (중간) | 0.5 |
| 480 (오른쪽 끝) | 1.0 |

---

#### Step 3: NDC 변환 (0~1 → -1~1)

```glsl
vec2 ndc = normalized * 2.0 - 1.0;
```

**계산**:
```
ndc = (0.604, 0.569) * 2.0 - 1.0
    = (1.208, 1.138) - (1.0, 1.0)
    = (0.208, 0.138)
```

**원리**:
- `* 2.0`: [0, 1] → [0, 2]
- `- 1.0`: [0, 2] → [-1, 1]

**변환 대응표**:

| 픽셀 좌표 | 정규화 | NDC |
|-----------|--------|-----|
| 0 | 0.0 | **-1.0** |
| 240 (중간) | 0.5 | **0.0** |
| 480 (끝) | 1.0 | **1.0** |

**의미**: OpenGL NDC 좌표계로 변환 완료

---

#### 수식 분해: 왜 나누고 * 2.0 하고 - 1.0 할까?

**전체 흐름 (화면 중앙 픽셀 240 예시)**:

```
픽셀 좌표 (x축)
├─────────┼─────────┤
0        240       480

    ↓ / 480 (정규화)

[0, 1] 범위
├─────────┼─────────┤
0.0      0.5       1.0

    ↓ * 2.0 (범위 확장)

[0, 2] 범위
├─────────┼─────────┤
0.0      1.0       2.0

    ↓ - 1.0 (원점 이동)

NDC [-1, 1]
├─────────┼─────────┤
-1.0     0.0       1.0
  ↑       ↑        ↑
 왼쪽    중앙    오른쪽
```

**각 단계의 역할**:

| 단계 | 수식 | 범위 변환 | 의미 |
|------|------|-----------|------|
| 1 | `/ viewsize` | `[0, 480]` → `[0, 1]` | 화면 크기 무관하게 정규화 |
| 2 | `* 2.0` | `[0, 1]` → `[0, 2]` | NDC 범위에 맞게 확장 |
| 3 | `- 1.0` | `[0, 2]` → `[-1, 1]` | 원점을 화면 중앙으로 이동 |

**왜 이 순서일까?**
- ✅ 단계별 의미가 명확 (정규화 → 확장 → 원점 이동)
- ✅ 0~1 정규화 과정이 직관적
- ✅ 다른 방식으로도 표현 가능하지만 이 방식이 가장 이해하기 쉬움

**동일한 계산 (다른 표현)**:
```glsl
// 모두 같은 결과:
ndc = (pixelPos / viewsize) * 2.0 - 1.0;
ndc = pixelPos * 2.0 / viewsize - 1.0;
ndc = (pixelPos * 2.0 - viewsize) / viewsize;
```

---

#### Step 4: Y축 반전

```glsl
ndc.y = -ndc.y;
```

**이유**: 좌표계 원점 위치 차이
- **픽셀 좌표 (좌상단 원점)**: y 증가 = 아래로 ↓
- **OpenGL NDC (좌하단 원점)**: y 증가 = 위로 ↑

→ y축을 반전시켜서 직관적인 좌표계 유지

**계산**:
```
ndc.y = 0.138 → -0.138
```

---

### 3.3 시각화

```
픽셀 좌표계 (480x720)
┌─────────────────┐
│ (0,0)           │ ← 좌상단 원점
│                 │
│     (240,360)   │ ← 중앙
│                 │
│           (480,720) ← 우하단
└─────────────────┘

         ↓ viewport 투영

NDC 좌표계
    y
    ↑
(-1,1) ─────── (1,1)
    │           │
────┼───────────┼──── x
    │  (0,0)    │
(-1,-1) ────── (1,-1)
```

---

### 3.4 Aspect Ratio가 자동 해결되는 이유

픽셀 좌표 `(100, 100)`을 입력하면:

```
x: 100 / 480 * 2 - 1 = 0.417 - 1 = -0.583
y: 100 / 720 * 2 - 1 = 0.278 - 1 = -0.722
```

**결과**:
- NDC에서 x, y 비율이 **viewport 비율에 자동으로 맞춰짐**
- 화면에서 정사각형으로 렌더링됨

**Aspect ratio 보정이 필요 없는 이유**:
- viewport 크기로 나누는 과정에서 자동으로 각 축의 비율이 반영됨
- 480과 720이라는 실제 픽셀 크기로 나누므로, 결과적으로 정규화된 비율이 자동 계산됨

## 4. 좌표계 선택

테트리스 게임에 적합한 좌표계 옵션:

### 4.1 좌상단 원점 (0,0) ~ (480, 720) ← **추천**

```
┌─────────────────┐
│ (0,0)     +x →  │
│   +y             │
│   ↓              │
│           (480,720)
└─────────────────┘
```

**장점**:
- ✅ Unity 2D UI, 대부분 2D 엔진 방식
- ✅ 테트리스 블록이 위→아래 떨어짐 (y 증가 = 아래)
- ✅ 격자 좌표와 매칭 쉬움
- ✅ 배열 인덱스와 직관적 대응

**사용 예시**:
```go
// 블록이 위에서 생성되어 아래로 떨어짐
location := types.NewVector2(240, 0)    // 화면 위
// ... 프레임마다 y 증가
location.Y += fallSpeed  // 아래로 이동
```

---

### 4.2 중앙 원점 (-240, -360) ~ (240, 360)

```
        y
        ↑
────────┼────────
        │ (0,0)
        ↓
```

**장점**:
- 회전/스케일 변환에 유리

**단점**:
- ❌ 테트리스 격자 좌표와 매칭 어려움
- ❌ 음수 좌표 처리 필요

---

### 4.3 좌하단 원점 (0,0) ~ (480, 720)

```
│           (480,720)
│   ↑              │
│   +y             │
│ (0,0)     +x →  │
└─────────────────┘
```

**장점**:
- OpenGL 전통 방식

**단점**:
- ❌ y축이 위로 증가 → 테트리스 블록 떨어뜨리기 비직관적

---

### 선택: 좌상단 원점

테트리스 게임 특성상 **좌상단 원점**이 가장 적합합니다.

---

## 5. 화면 밖 좌표 처리

### 5.1 화면 밖 좌표도 자유롭게 사용 가능

Unity나 다른 게임 엔진처럼 **화면 밖 좌표**도 완벽히 지원됩니다.

**예시**:
```go
// 화면 왼쪽 밖
location := types.NewVector2(-100, 360)  // ✅ 가능

// 화면 위쪽 밖 (테트리스 블록 생성 위치)
location := types.NewVector2(240, -50)   // ✅ 가능

// 화면 오른쪽 밖
location := types.NewVector2(600, 360)   // ✅ 가능
```

---

### 5.2 OpenGL 자동 클리핑

OpenGL은 **NDC 범위 [-1, 1] 밖의 좌표를 자동으로 클리핑**합니다.

**예시 계산** (화면 왼쪽 밖):

```glsl
pixelPos = (-100, 360)

// 1. 정규화
normalized = (-100/480, 360/720) = (-0.208, 0.5)

// 2. NDC 변환
ndc = (-0.208 * 2 - 1, 0.5 * 2 - 1)
    = (-1.416, 0.0)

// 3. OpenGL 클리핑
// NDC.x < -1.0 이므로 화면 밖 → 렌더링 안 됨
```

**클리핑 테이블**:

| 픽셀 좌표 | NDC | 결과 |
|-----------|-----|------|
| (-100, 360) | (-1.416, 0.0) | 화면 왼쪽 밖 → 안 보임 |
| (240, 360) | (0.0, 0.0) | 화면 중앙 → 보임 |
| (600, 360) | (1.5, 0.0) | 화면 오른쪽 밖 → 안 보임 |
| (240, -50) | (0.0, -1.139) | 화면 위쪽 밖 → 안 보임 |
| (240, 800) | (0.0, 1.222) | 화면 아래쪽 밖 → 안 보임 |

---

### 5.3 Unity와 비교

```csharp
// Unity (픽셀 좌표)
transform.position = new Vector2(-100, 360);  // 화면 밖 OK
```

```go
// 우리 시스템 (픽셀 좌표)
location := types.NewVector2(-100, 360)  // 화면 밖 OK
```

**완전히 동일하게 작동합니다!** ✨

---

### 5.4 실제 사용 시나리오: 테트리스 블록 생성

```go
// 블록을 화면 위 (y = -50)에서 생성
location := types.NewVector2(240, -50)  // 화면 밖

// 게임 루프에서 블록이 떨어지면서 y 좌표 증가
func Update(deltaTime float64) {
    location.Y += fallSpeed * deltaTime

    // y = -50 → 화면 밖 (안 보임)
    // y = 0   → 화면 위쪽 경계에 나타남
    // y = 100 → 화면 안에서 보임
    // y = 720 → 화면 아래쪽 경계
}
```

## 요약

1. **문제**: NDC 좌표계를 직접 사용하여 aspect ratio 미반영 → 정가각형이 찌그러짐
2. **해결**: Viewport 투영 (픽셀 좌표계) 도입
3. **원리**: 픽셀 좌표 → 정규화(0~1) → NDC(-1~1) → y축 반전
4. **좌표계**: 좌상단 원점 (0,0) ~ (480, 720)
5. **장점**:
   - ✅ 직관적인 픽셀 단위 좌표
   - ✅ Unity 등 다른 엔진과 유사
   - ✅ Aspect ratio 자동 해결
   - ✅ 화면 밖 좌표 자유롭게 사용 가능
   - ✅ 테트리스 격자 좌표와 자연스럽게 매칭
